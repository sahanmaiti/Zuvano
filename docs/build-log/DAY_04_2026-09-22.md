# Zuvano Day 4 Build Log

## Metadata

- **Date:** 2026-09-22
- **Day:** Day 4 — Action Drafts + Core Review UX
- **Phase:** Implementation
- **Goal:** Transform actionable intents into editable Action Drafts and build the central Zuvano Review experience

## 1. What was implemented

Inserted the `generatingDrafts` pipeline stage between understanding and review. Replaced the Day 3 intent milestone UI with full Action Review (edit, skip/restore, source peek, validation, Create controls). No EventKit execution.

### Domain + persistence

- **`ActionKind`**, **`ConfirmationState`**, **`ExecutionState`**, **`ActionDateTime`**, **`ActionDraftSnapshot`**, **`ReviewOutcome`**, **`DraftValidationConcern`**
- **`ActionDraftRecord`** SwiftData model with flattened `ActionDateTime` fields
- **`IntakeRecord.drafts`** cascade relationship
- **`ActionStore`** draft CRUD: `fetchDrafts`, `replaceDrafts`, `updateDraft`, `deleteDrafts`
- **`ModelContainer`** registers `ActionDraftRecord`

### Normalization + mapping

- **`IntentNormalizer`:** pure, deterministic weekday/time resolution; preserves `rawExpression`; marks ambiguity; never invents `startDate`
- **`DraftMapper`:** maps `meeting → calendarEvent`, `task/reminder/commitment → reminder`; derives titles from source phrases
- **`DraftValidator`:** calendar requires title + start date; reminder requires title only; ambiguous drafts allowed when required fields present

### Pipeline integration

- **`IntakePipeline.runDraftGeneration`:** filter → `generatingDrafts` → normalize → map → persist → `readyForReview`
- Draft generation failure: `failedStage = draftGeneration`, `draftGenerationFailed`
- **`retryDraftGeneration`** re-runs understanding from `extractedText`, then draft generation
- Launch recovery: `.readyForReview` loads persisted drafts (no re-understanding); `.generatingDrafts` interrupted → failed at `draftGeneration`

### Action Review UI (S3–S6)

- **`ActionReviewView`:** inset grouped list of draft rows; header with count + **View source**; empty state (S6); batch **Create N Ready** + **Create Selected**; invalid-count footnote
- **`DraftRowView`:** proposal states (proposal, needs attention, about…, skipped); title-primary hierarchy; visible **Restore** on skipped rows; VoiceOver label + value + hints
- **`EditDraftSheet`:** Form with title, type, dates, location, person, notes; unsaved dismiss confirmation; clears ambiguity when exact date set
- **`SourceTextSheet`:** read-only extracted text peek
- **Deleted** `UnderstandingResultsView` (Day 3 milestone)

### Coordinator

- **`AppFlow.actionReview`** replaces `.understandingResults`
- Draft mutations persist via `ActionStore`: edit, skip, restore, create (sets `confirmationState = confirmed` locally — no EventKit)

### Tests

- 42 Swift Testing unit cases (16 existing updated + 26 new/expanded)
- New: `IntentNormalizerTests`, `DraftValidatorTests`, `DraftGenerationTests`

**Not implemented (by design for Day 4):** EventKit execution, permission flow, `executing`/`executed` row states, Done gating until all drafts terminal, contextual Create copy (Add to Calendar / Add Reminder).

## 3. Architecture / product decisions

- **Orchestrator owns draft creation.** `IntentNormalizer` is pure; `DraftMapper` maps normalized intents; pipeline persists via `ActionStore`.
- **Zero drafts is success.** Empty actionable → `readyForReview` + S6, not pipeline failure.
- **Create on Day 4 sets `confirmed` only.** No EventKit, no `executing` state. Execution UI deferred to Day 5.
- **Launch recovery loads drafts.** `.readyForReview` no longer re-runs understanding.
- **SwiftData schema change.** Adding `ActionDraftRecord` requires clean simulator install for dev builds.

## 6. Problems encountered

1. **DraftMapper regex API:** Swift `Regex` literals incompatible with `String.range(of:options:.regularExpression)` — switched to `NSRegularExpression`.
2. **Test return type drift:** Pipeline now returns `ReviewOutcome` with `drafts` instead of `UnderstandingOutcome.filteredIntents`.
3. **SwiftData schema:** New `ActionDraftRecord` entity requires updated `ModelContainer` in tests and app.
4. **Design review P1/P2:** Title hierarchy, batch select wiring, skipped Restore affordance, accessibility hints.

## 7. Fixes applied
