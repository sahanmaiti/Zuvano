## 3. Architecture / product decisions

- **IntakePipeline as Sendable struct** (not a separate actor): coordinates async calls into `@ModelActor ActionStore`; returns `IntakeSnapshot` to avoid crossing SwiftData model instances across isolation domains.
- **ActionStore returns snapshots only** to presentation and pipeline layers; `IntakeRecord` stays inside the model actor.
- **Successful extraction advances to `.understanding`** in persistence (next pipeline stage per data model) even though understanding is not implemented until Day 3.
- **ExtractionCompleteView** is a deliberate Day 2 milestone UI to verify extracted text end-to-end; it will be replaced by Processing → Understanding → Review in Day 3+.
- **Temp images:** saved on intake creation for image sources; retained on OCR failure; deleted on successful OCR, manual text entry, or discard/purge.
- **Swift 6 concurrency:** domain types and pipeline methods marked `nonisolated` where needed under default MainActor isolation; `TemporaryImageStore` uses `nonisolated` file I/O.
- **Paste authorization:** iOS 16+ requires a visible, unobscured `UIPasteControl` (or SwiftUI `PasteButton`) as the tap target. Custom overlay buttons cannot receive authorized paste. Clipboard availability for styling uses `UIPasteboard.general.hasStrings` only.
- **Paste control recreation:** `UIPasteControl.Configuration` is immutable after attach. Color changes recreate the control via SwiftUI `.id(hasClipboardText)` rather than mutating configuration in place.

## 6. Problems encountered

1. **Swift 6 MainActor default isolation:** Domain structs, `TemporaryImageStore`, and `IntakePipeline` required `nonisolated` annotations to cross actor boundaries and compile in tests.
2. **`@ModelActor ActionStore` + `IntakeRecord`:** Returning `IntakeRecord` from store methods caused region isolation errors; fixed by returning `IntakeSnapshot` only.
3. **PBErrorDomain Code=13:** Direct `UIPasteboard` reads and clipboard probing blocked on iOS 16+; required system paste control.
4. **Paste styling attempts broke behavior:** Overlay/background decorative buttons blocked taps or caused iOS to disable hidden `UIPasteControl`.
5. **`UIViewRepresentable` height expansion:** Unconstrained paste host view expanded inside `ScrollView` and intercepted taps on Choose Photo / Enter Text.
6. **Immutable paste configuration crash:** Mutating `pasteControl.configuration` after attach raised `NSInternalInconsistencyException`.
7. **Extraction header clipping:** Zero `listRowInsets` plus `frame(maxWidth:)` on `Text` clipped leading glyphs on Extracted Text screen.
8. **Clipboard refresh (Day 1):** Computed `clipboardHasText` did not trigger Observation updates; removed with coordinator-based flow.

## 8. Known limitations / unfinished work

- **No formal Vision OCR device benchmark** — unit tests use passthrough/stub extractors; screenshot OCR quality on varied images unverified
- **PhotosPicker `Data` transferable** — may fail for some image formats; not validated with all photo types
- **ExtractionCompleteView** is a temporary Day 2 surface; not in final IA (Processing → Review)
- **Understanding engine** not implemented (Day 3); understanding retry only resets pipeline state
- **Share Extension** not implemented (Day 6)
- **UI tests** still template-only; no automated paste/OCR flow coverage
- **Paste button appearance** uses system `UIPasteControl` chrome, not a pixel-perfect match to SwiftUI `.bordered` buttons in all themes
- **`hasStrings` clipboard hint** may not reflect all pasteable content types (e.g. some rich clipboard payloads)
