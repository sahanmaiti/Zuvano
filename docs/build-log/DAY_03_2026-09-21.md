## 1. What was implemented

Connected the Day 2 extraction pipeline to on-device understanding, intent extraction, and the user-actionable filter. Replaced the Day 2 extraction-complete placeholder with a temporary Review milestone surface.

### Core intelligence (Day 3 scope)

- **Domain types:** `Intent`, `IntentEntity`, `UnderstandingResult`, `UnderstandingOutcome`, `EngineKind`, `IntentKind`, `EntityKind`, `ConfidenceLevel`, `IntentAttribution`, `UnderstandingError`
- **`UnderstandingEngine` protocol** with `MockUnderstandingEngine` for tests
- **`FoundationModelsUnderstandingEngine`:** runtime-gated via `SystemLanguageModel.default.availability`; structured output via `@Generable` types; validated mapping to domain intents
- **`FallbackUnderstandingEngine`:** deterministic, conservative pattern matching; does not fabricate intents from questions, other-person commitments, hypotheticals, or entity-only mentions
- **`CompositeUnderstandingEngine`:** primary → fallback selection per architecture §10
- **`UserActionableFilter`:** orchestrator rule dropping non-user actions and MVP follow-ups

### Pipeline integration

- **`IntakePipeline`** now chains extraction → understanding → filter → `readyForReview`
- Understanding failure sets `failedStage = understanding` with retryable `FailureReason`
- `retryUnderstanding`, `continueUnderstanding`, manual text, and OCR retry all re-enter understanding using persisted `extractedText`
- Launch recovery resumes `.understanding` and `.readyForReview` intakes by re-running understanding

### UI / flow

- **`AppFlowCoordinator`:** holds transient `filteredIntents`; routes to processing through understanding
- **`UnderstandingResultsView`:** temporary Day 3 milestone (S6 empty + proposed-action list); no model jargon; replaced `ExtractionCompleteView`
- Processing copy already included **Understanding the conversation…** phase

### Tests

- 16 Swift Testing unit cases total (9 updated extraction + 7 new understanding/filter cases)
- Controlled test set covers worked example, other-person drop, questions, hypotheticals, follow-up MVP drop, composite fallback, understanding failure + retry

**Not implemented (by design for Day 3):** `IntentNormalizer`, Action Draft persistence/generation, Action Review Create flow, EventKit, Share Extension.

## 3. Architecture / product decisions

- **Intents remain transient.** Only `IntakeSnapshot` is persisted through understanding; filtered intents live in the coordinator until Day 4 draft persistence.
- **Empty actionable is success.** Filtered zero intents → `readyForReview` + S6 empty UI, not pipeline failure.
- **Fallback never fabricates.** Conservative regex patterns only; prefer empty over invented actions.
- **Composite engine in production wiring.** Primary FM failure or unavailability falls back deterministically without exposing engine details in UI.
- **Day 3 Review surface is temporary.** Shows proposed-action language without Create/Edit/Skip; Day 4 replaces with full Action Review + drafts.
