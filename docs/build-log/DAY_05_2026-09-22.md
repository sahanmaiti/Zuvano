## 1. What was implemented

Wired the full Create → permission → persist `executing` → EventKit → persist result path. Added launch recovery for interrupted execution. Updated Action Review for execution states, permission UX, retry/resume, and Done gating.

### Execution module

- **`DraftExecutionService`** actor: owns `EKEventStore`; lazy Calendar write-only + Reminders full access; creates `EKEvent` / `EKReminder`; serializes in-flight work per `draft.id`
- **`ActionExecutor`** protocol + **`ExecutionResult`**, **`ExecutionFailure`**, **`DraftExecutionEligibility`**
- **`PermissionKind`**, **`PermissionOutcome`** in domain types
- Calendar events: title, start/end (default 1h duration), location, notes, person in notes
- Reminders: title, optional due date components, notes

### Orchestration

- **`AppFlowCoordinator`**: validate → confirm → permission (pre-alert + system prompt) → persist `executing` → EventKit → persist `executed`/`failed`
- Batch create / Create Selected with union permission request
- **`retryExecution`** for failed drafts; **`resumeExecution`** for `confirmed+notStarted` after permission grant
- **`skipDraft`** allowed for `pending` or `confirmed+notStarted` (permission-denied recovery)
- Launch recovery via **`IntakePipeline.recoverDraftExecutionStates`**: `executing+id→executed`, `executing+no id→failed/interrupted`; never auto EventKit

### Review UI

- Row states: Creating…, Created, Couldn't create + Retry, Waiting for access + Try Again / Open Settings
- Permission pre-alert (Continue) with Calendar/Reminders copy
- Inline permission banner when denied
- Contextual Create copy (Add to Calendar / Add Reminder / mixed batch)
- Done disabled until all drafts terminal
- Accessibility announcements on create success/failure

### Info.plist

- `NSCalendarsWriteOnlyAccessUsageDescription`
- `NSRemindersFullAccessUsageDescription`

### Tests

- **`ExecutionTests`**: 9 new cases (recovery, eligibility, terminal states, mock executor)

**Not implemented (by design for Day 5):** Share Extension, full Day 6 polish, runtime device EventKit walkthrough in CI.

## 3. Architecture / product decisions

- **EventKit only in `DraftExecutionService` actor.** `IntakePipeline` never calls EventKit; recovery is state repair only.
- **Persist `executing` before EventKit** per data model §7/§15.
- **Single shared `EKEventStore`** inside the execution actor.
- **Calendar write-only access** (`requestWriteOnlyAccessToEvents`); Reminders full access (no write-only API).
- **Default calendar event duration:** 1 hour when end date missing.
- **Permission pre-alert once per session** before first system prompt.
- **Resume path:** `confirmed+notStarted` drafts can Try Again after granting permission; Skip allowed per data model `confirmed→rejected` when `notStarted`.
