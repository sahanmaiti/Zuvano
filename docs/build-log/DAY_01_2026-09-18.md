## 3. Architecture / product decisions

- **Project location:** `Zuvano/Zuvano.xcodeproj` under repo root (nested `Zuvano/` folder from Xcode template).
- **Bundle ID:** `com.zuvano.app`.
- **iPhone-only:** `TARGETED_DEVICE_FAMILY = 1`, `SUPPORTED_PLATFORMS = iphoneos iphonesimulator`.
- **Swift 6 + strict concurrency:** `SWIFT_VERSION = 6.0`, `SWIFT_STRICT_CONCURRENCY = complete`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`.
- **Observation:** `HomeViewModel` is `@Observable` / `@MainActor`; photo selection stays in view `@State` (PhotosUI type boundary).
- **Clipboard testability:** `ClipboardChecking` protocol with `LiveClipboardChecker` and `StubClipboardChecker` for previews.
- **Day 1 stubs:** `pasteTapped()` is a no-op; photo `onChange` stores selection locally only.
- **Signing:** Simulator builds use `CODE_SIGN_IDENTITY = -` and `CODE_SIGNING_ALLOWED=NO` via xcodebuild flags; no development team configured yet.
- **Design tokens + concurrency:** Pure `CGFloat` spacing constants are `nonisolated` so they can be referenced from `@Sendable` view builder closures (e.g. `PhotosPicker` label) without crossing MainActor isolation.
- **Editor tooling:** SourceKit-LSP uses `xcode-build-server` BSP bridge; workspace must be opened at repo root, not only the inner source folder.

## 6. Problems encountered

1. **Xcode MCP signing:** `BuildProject` / `RunProject` failed without a development team because the multi-platform template enabled app sandbox / entitlements requiring signing.
2. **PhotosPickerItem in ViewModel:** `PhotosPickerItem` did not resolve in `HomeViewModel.swift` when imported via PhotosUI alone; moved photo selection to view `@State`.
3. **Simulator from sandboxed shell:** `simctl` failed with CoreSimulator connection errors in restricted sandbox; succeeded with full permissions.
4. **Test targets:** Still on iOS 27.0 / multi-platform defaults from template; app target correctly set to iOS 26.0 iPhone-only.
5. **Cursor false diagnostics:** SourceKit-LSP reported `No such module 'UIKit'`, unresolved `ZuvanoColors`, and similar errors despite clean Xcode builds — no BSP bridge configured.
6. **Swift 6 Sendable closure:** `ZuvanoSpacing.minimumTouchTarget` triggered *Main actor-isolated static property can not be referenced from a Sendable closure* inside `PhotosPicker` label under default MainActor isolation.

## 7. Fixes applied

- Used `xcodebuild` with `CODE_SIGN_IDENTITY=- CODE_SIGNING_ALLOWED=NO` for simulator build/test.
- Set `ENABLE_APP_SANDBOX = NO` on app target via Xcode MCP.
- Moved `selectedPhotoItem` from `HomeViewModel` to `HomeView` `@State`.
- Ran simulator install/launch outside sandbox.
- Installed `xcode-build-server` via Homebrew; generated `buildServer.json` and `.compile` from Xcode build log; added `.vscode` settings/tasks and `docs/SETUP_README.md` SourceKit section.
- Marked `ZuvanoSpacing` static constants `nonisolated`; switched import from `SwiftUI` to `CoreGraphics`.
