# Zuvano Day 8 Build Log

## Metadata

- **Date:** 2026-09-26
- **Day:** Day 8 — EventKit execution fix (Calendar + Reminders)
- **Phase:** Execution hardening
- **Goal:** Fix confirmed runtime failure when creating Calendar events and Reminders after draft approval; differentiate failures; preserve retry/idempotency

## 1. What was implemented

### Root cause (confirmed)

Execution reached EventKit after permission was treated as granted, but failed during container resolution or save. Contributing issues in `DraftExecutionService`:

1. `EKEventStore` was created before authorization and not recreated after a successful permission transition; sources were not refreshed (`refreshSourcesIfNecessary()` never called).
2. Mid-resolution store replacement could run **after** `EKEvent` / `EKReminder` were already bound to the pre-transition store, causing cross-store saves.
3. `.writeOnly` calendar access was treated as granted, blocking a full-access upgrade path needed to list calendars and resolve writable containers.
4. Permission, missing writable container, and save failures all mapped to generic `calendarFailed` / `reminderFailed`, and the review row ignored `executionError` except `.interrupted`.

### EventKit store lifecycle

- Added `EventKitExecutionStore` protocol with `LiveEventKitExecutionStore` adapter.
- After permission transitions to `.fullAccess`, recreate `EKEventStore` once and refresh sources; on steady state, refresh only during resolution.
- Calendar events and reminders are built and saved on the same store instance used for resolution (resolve container **before** item construction in the live adapter).

### Writable container resolution

- Pure resolution in `EventKitCalendarResolution` (default → writable Zuvano → any writable → create Zuvano on usable sources; skip birthdays/subscribed; reuse existing writable Zuvano per source).

### Typed failures

- Extended `ExecutionFailure` and persisted `FailureReason` with `noWritableCalendar`, `noWritableReminderList`, `calendarSaveFailed`, `reminderSaveFailed` (legacy `calendarFailed` / `reminderFailed` retained for existing SwiftData records).

### UI

- `DraftRowView` maps execution errors to specific copy; permission failures on failed rows include **Open Settings**.

### Idempotency

- `AppFlowCoordinator` tracks in-flight draft IDs, skips duplicate `executeDraft` entry, re-reads draft after persisting `executing`, and does not persist failure for `alreadyInFlight`.

### Tests

- `DraftExecutionServiceTests` with `MockEventKitExecutionStore` (no simulator Calendar DB).
- Expanded `EventKitCalendarResolutionTests`.

**Not modified:** extraction, OCR, understanding, intent normalization, draft generation.

## 3. Architecture / product decisions

- **Full calendar access only** for execution (not write-only); aligns with listing/creating calendars.
- **Frozen `docs/03_DATA_MODEL.md` not edited**; new `FailureReason` raw values are backward-compatible via string storage.
- **Minimal store seam** for testability without reading the simulator Calendar database.
